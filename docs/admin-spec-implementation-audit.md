## 2. 이번 보완에서 완료한 항목

- 전체 URL을 붙여넣었을 때 `https:`를 설문 ID로 잘못 인식하던 관리자 홈 검색을 수정했다.
- 관리자 모달에서 복구·제한 해제는 사유 분류를 숨기고, 운영팀 지정·해제는 메모를 선택 입력으로 맞췄다.
- `PURGED`, `WEEK_LOCKED`, `WRONG_STEP`, 401·403·404 오류를 사용자용 메시지로 정규화했다.
- 회원 상세와 주간 응답 화면에서도 답변 원문 열람 기록이 남도록 통합했다.
- 주간 응답 상세가 URL의 주차를 기준으로 필터링되도록 보완했다.
- 데모 흐름에서 운영 삭제 복구 상태, 부정 응답 중복 방지·주간 점수 차감·상세 지표 갱신을 연결했다.
- 보상 목록의 1·2·3위와 발송 수, 실데이터의 이메일·보상 내용·발송 시각 표시를 보완했다.
- 운영 삭제된 사용자 설문은 결과 조회만 유지하고 링크 공유와 직접 마감 동작을 숨겼다.
- 설문 모집 중 배지를 명세의 파란색으로 분리하고 긴 표 셀·메모·모달 오버플로를 보완했다.
- 설문·회원·팀·조치 기록 목록에 20개 페이지네이션을 추가하고 검색·필터·기간·정렬·페이지를 URL에 보존했다.
- 설문 주소 찾기에 잘못된 입력과 존재하지 않는 ID 오류를 추가했다.
- 운영 삭제 상세에 사유, 메모, 처리자, 처리 시각을 표시하고 파기 후 복구 버튼을 숨겼다.
- 복구 시 마감일 전이면 `active`, 이후면 `closed`가 되도록 서버 조치를 수정했다.
- 응답 보기에서 실제 질문과 답변을 함께 표시하고 열람 감사 로그를 남기도록 했다.
- 부정 응답 처리에 `PURGED`, `WEEK_LOCKED`, 중복 제외 방어를 추가했다.
- 회원 상세에 게시 설문, 제출 응답, 조치 이력 탭을 추가했다.
- 이용 제한 기간 7일·30일·무기한과 명세의 사유 분류를 적용했다.
- 팀 상세에 팀 설문 목록을 추가하고 데모 데이터에서 팀 이름 변경이 사용자 팀과 게시 명의에 연결되게 했다.
- 리더보드 주차를 URL에 남기고 운영팀 배지를 표시했다.
- 정산 1단계 후보 확인 체크, 2단계 순위 미리보기, 3단계 동점 안내, 4단계 대상자, 5단계 발송 기록 UI를 보강했다.
- 보상 공지에 사용자 화면 미리보기와 동점 규칙을 추가하고 사용자 리더보드의 문구 하드코딩을 제거했다.
- 관리자 조치 중 로딩, 중복 클릭 방지, 실패 메시지, 재시도를 추가했다.
- 관리자 상단 바를 일반 서비스와 구분되는 짙은 색으로 변경했다.

## 4. 화면별 판정

### 권한과 공통 레이아웃

- ✅ 일반 로그인 재사용, 별도 관리자 로그인 없음
- ✅ `profile.role === 'ADMIN'` 메뉴 및 라우트 가드
- ✅ 일반 사용자의 관리자 URL 직접 접근 차단과 403 안내 화면
- ✅ 정확히 6개 메뉴, 활성 메뉴, 관리자 닉네임, 서비스 복귀
- 🟡 실제 백엔드의 `/admin` REST 403은 없음. Supabase RLS/RPC 권한 검사로 구현됨
- 🔵 실계정에서 새로고침·로그아웃·권한 유지 브라우저 검증 필요

### 관리자 홈

- ✅ URL/ID 파싱, 없는 설문과 잘못된 입력 오류
- ✅ 가입자·게시 설문·응답 수 카드와 오늘/이번 주 값
- ✅ 처리할 일 이동 및 빈 상태
- 🟡 운영 DB의 동점 추첨 필요 항목은 별도 계산이 부족함

### 설문

- ✅ 검색, 상태·게시일 필터, URL 보존, 20개 페이지 이동, 빈 상태
- ✅ 상세 정보, 3개 탭, 읽기 전용 문항, 응답 필터
- ✅ 운영 삭제/복구 조건, 삭제 상세, 마감일 기준 복구
- ✅ 답변 열람 로그, 부정 응답 중복/PURGED/WEEK_LOCKED 방어
- 🟡 운영 데이터의 owner 링크와 서버 집계 카운트가 미완성
- ❌ `GET /admin/responses/:id` REST endpoint 및 표준 오류 body 없음

### 회원

- ✅ 목록 검색·필터·정렬·페이지 이동
- ✅ 프로필, 주간 지표, 제한 정보, 상태별 버튼
- ✅ 게시 설문·제출 응답·조치 이력 탭
- ✅ 제한 기간과 사유, 서버 생성 닉네임, 운영팀 배지
- 🟡 운영 DB 목록의 설문/응답/경고 집계값을 한 번에 반환하는 API 없음
- ❌ 실 이메일 발송 worker 없음

### 팀

- ✅ 팀/팀원 검색, 목록 정보, 팀장 표시, 팀 설문, 조치 이력
- ✅ 내보내기·해산 기능 없음
- ✅ 강제 이름 형식과 데모 사용자 화면/게시 명의 연동
- 🟡 실제 사용자 팀 기능과 관리자 팀 테이블의 데이터 원천이 다름

### 리더보드와 보상

- ✅ 주차 URL 유지, 전체 행, 경쟁 순위 `1,2,2,4`, 특수 상태 표시
- ✅ 정산 화면 5단계와 전원 확인 전 버튼 비활성화
- ✅ 공지 입력·미리보기·저장·사용자 문구 반영
- 🟡 과거 주차 데이터, 동점 추첨 결과 영속화, 단계별 독립 RPC가 불완전
- ❌ 명세의 `WRONG_STEP` 표준 오류 계약 없음
- ❌ 3명 발송 완료 후 서버 자동 완료 처리 없음

### 조치 기록과 사용자 연동

- ✅ 종류·기간·처리자·대상 필터, 20개 페이지 이동, 대상 링크
- ✅ 수정·삭제 기능 없음
- ✅ 사용자 내 설문 운영 삭제, 제한 화면, 보상 문구 연동
- 🟡 팀 화면은 데모 저장소에서만 즉시 연결됨
- 🔵 조치 후 뒤로가기·새로고침·다른 탭 동기화 브라우저 검증 필요

## 5. API 계약 대조

| Method | 명세 Endpoint | Frontend 호출 존재 | 실제 연결 | 요청/응답 일치 | 상태 |
|---|---|---|---|---|---|
| GET | `/admin/summary` | RPC 대응 | Supabase RPC | 불일치 | 🟡 |
| GET | `/admin/surveys`, `/:id`, `/:id/responses` | 있음 | Supabase select | 페이지 응답 불일치 | 🟡 |

| POST | 설문 remove/restore, 응답 exclude | 있음 | 통합 RPC | endpoint·오류 body 불일치 | 🟡 |
| GET/POST | 회원 목록·상세·탭·조치 | 대부분 있음 | select + 통합 RPC | 집계·endpoint 불일치 | 🟡 |
| GET/POST | 팀 목록·상세·rename | 있음 | select + 통합 RPC | 실제 사용자 팀과 분리 | 🟡 |
| GET | `/admin/leaderboard` | 있음 | RPC | week 입력 미반영 | 🟡 |

| GET | `/admin/logs` | 있음 | Supabase select | 서버 페이지네이션 없음 | 🟡 |

## 7. 우선 수정 순서

1. Supabase 또는 별도 백엔드에 실제 운영 환경을 연결하고 관리자 마이그레이션을 적용한다.
2. 이메일 outbox 소비 worker를 연결하고 성공·실패·재시도 상태를 저장한다.
3. 명세 REST 계약을 유지할지 Supabase RPC 계약으로 공식 변경할지 결정한다.
4. 정산 review/lock/lottery/finalize/sent를 독립 트랜잭션으로 구현한다.
5. 서버 페이지네이션과 집계 필드를 구현한다.
6. 사용자 팀 기능을 관리자와 같은 데이터 원천으로 이전한다.
7. 관리자·일반·제한 계정으로 실제 브라우저 회귀 테스트를 수행한다.

## 8. 실행 검증 범위

프로덕션 빌드, 기존 정책 테스트, 정적 라우트 응답은 자동 검증한다. 다만 이 환경에서는 브라우저 제어 세션을 연결할 수 없어 클릭, 모달 키보드 포커스, 뒤로가기, 새로고침 후 화면 상태, 실제 계정별 권한 전환은 실행 검증 필요로 남겼다.
